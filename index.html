01 · The decision

Which governance feature earns next quarter's team?

I'm playing the PM for catalog governance. Engineering can fully staff one of five candidates next quarter. A spreadsheet RICE score would crown a winner to two decimals. But reach is a forecast, impact is a judgment call, and effort estimates slip. The real question: is the winner robust, or a coin flip dressed up as a ranking?

customer_problem

Tags stop at the first copy

A steward tags customers.email as PII. An analyst runs CREATE TABLE AS SELECT, and the derived table starts life untagged and unmasked. In a big lakehouse, most sensitive data lives in derived tables, so governance quietly leaks downstream.

Pinned from: steward interviews (simulated) · 6 of 8 named "derived tables" as the top audit gap
proposed_change

Pick the feature the futures agree on

Score each candidate with RICE where every input is a range, not a point. Simulate 1,000s of draws, record who ranks #1 each time, and commit only if the leader wins in at least 60% of futures. Otherwise, spend two weeks shrinking the widest range first.

Decision rule set before looking at results, so the sim can't be tuned to a favorite.

04 · The math, from my Monte Carlo course

A ranking is a probability in disguise

Fraction-of-hits estimation (Ch. 1). The classic warm-up throws random darts at a square and counts the share that land inside a shape to estimate its area. Here the "shape" is the set of futures where a feature comes out on top. Each simulated future is a dart; the share of darts in feature A's region estimates P(A ranks #1).

Why it's trustworthy. The number of wins in n futures is Binomial(n, p), so the share p̂ is unbiased and its variance is p(1−p)/n. Doubling the futures shrinks the standard error by about 30%. The Strong Law of Large Numbers says the running share settles on the true p, which is exactly the line you watch flatten in the chart.

Expectations as averages. Mean RICE is just the sample average of R·I·C/E across draws. Note it is not the RICE of the average inputs, because dividing by an uncertain effort pulls the average up (Jensen's inequality). Spreadsheets miss that.

p̂ = (1/n) Σ 1[ feature k has max RICE in draw i ]

SE(p̂) = √( p̂(1−p̂) / n )

95% band: p̂ ± 1.96·SE

Product example. With 5,000 futures and p̂ = 0.62, SE ≈ 0.0069, so the band is roughly 0.61 to 0.63. That's tight enough to say "the leader wins about 6 in 10 futures." It does not say the leader is great. It says how much the fog could reshuffle the order, which is what a roadmap review actually argues about.

Seeded randomness. I use a fixed-seed generator so a reviewer who presses "Run" sees the same numbers I quoted. Change the seed and the estimate should move only within its band. If it moves more, n is too small.

05 · How I'd run it on real data

From guesses to measured ranges

The ranges above are simulated. In practice I'd fit Reach from system tables, Effort from historical estimate-vs-actual slippage, and keep Impact and Confidence as explicit, reviewed judgment calls. Table names are illustrative.

-- Reach: workspaces creating derived tables
-- from tagged sources (last 90 days)
WITH tagged_src AS (
  SELECT DISTINCT table_full_name
  FROM gov.catalog_tags
  WHERE tag_name IN ('pii','phi','pci')
),
derived AS (
  SELECT l.workspace_id, l.target_table
  FROM gov.table_lineage l
  JOIN tagged_src s
    ON l.source_table = s.table_full_name
  WHERE l.event_date >= current_date() - 90
)
SELECT
  count(DISTINCT workspace_id)  AS reach_ws,
  avg(CASE WHEN t.tag_name IS NULL
      THEN 1 ELSE 0 END)       AS untagged_share
FROM derived d
LEFT JOIN gov.catalog_tags t
  ON d.target_table = t.table_full_name;
import numpy as np
rng = np.random.default_rng(102)

# ranges: (low, high) per feature, pulled from
# the query above + estimate-slippage history
R = spark.table("pm.rice_ranges").toPandas()
n, k = 20_000, len(R)

draw = lambda lo, hi: rng.uniform(lo, hi, (n, k))
rice = (draw(R.reach_lo,  R.reach_hi)
      * draw(R.impact_lo, R.impact_hi)
      * draw(R.conf_lo,   R.conf_hi)
      / draw(R.eff_lo,    R.eff_hi))

wins = np.bincount(rice.argmax(1), minlength=k)
p = wins / n
se = np.sqrt(p * (1 - p) / n)
for name, pk, s in zip(R.feature, p, se):
    print(f"{name:28s} {pk:.3f} ± {1.96*s:.3f}")
